# Changelog of the libretro core

What changed in the libretro core of this fork, newest first. Changes that come with a merge of upstream Xenia Edge are in upstream's own history; a merge is noted here with the upstream commit it brought in.

## Unreleased

- Native D3D12 vertex/domain and pixel shaders retain their bytecode directly on the exact translation owner, replacing two nested cache maps and five cache-lock sites with C89 libretro-common atomic publication. Consumers borrow the existing binary without a staging copy; failed emission is cached independently from pending work. Joined shutdown and virtual shader destruction release the binary. Shared binding-generation and geometry-cache locks remain; shader output and audio scheduling are unchanged.

- Move SVOD fragment enumeration, sizing and payload reads to libretro-common VFS with a fixed C89 fragment table. Mount parsing borrows mapped sectors or reuses four bounded sector slots; filename decoding reuses mount-only scratch. Remove native filesystem queries, the fragment map and temporary name vectors, while reading payloads directly into caller storage. Failed transfers retain their successful byte count, malformed directory entries reject safely, and all opened fragments close on failure. Unmapped VFS cursors retain necessary exclusion; cold fragment opens and final guest copies remain.

- Fix XContent container selection on native file streams: libretro VFS seek returns zero on success, not the resulting offset. Correct the probe and its fake VFS fixture, and exercise real files through both the C89 probe and native container factory. This repairs a regression introduced by the earlier header migration.

- Avoid duplicate texture conversion calls when several fetch constants reference the same texture owner, for both renderer paths. Dirty batches deduplicate their existing pointer span in stable order before the authoritative dirty snapshot. Distinct signed/unsigned owners and failure/invalidation retries remain separate. Clean batches bypass compaction; the hint scan stops after the first dirty owner. The C89 filter adds no allocation or persistent texture metadata and uses 128 bytes of temporary hash indices only for larger distinct sets. The native regression reduces 64 identical-owner conversion calls to one; real GPU timing and gameplay gains remain unmeasured.

- Fail content loading cleanly when the frontend rejects the pixel format or Vulkan/D3D12 hardware rendering. Pixel validation precedes GPU context creation, and failed loads clear pending audio ownership, fractional cadence, disc entries and title patch options before retry. Vulkan/D3D12 provider failures return an error rather than terminating the frontend, and D3D12 stops before dereferencing a missing provider. Existing Vulkan v2-to-v1 negotiation fallback is preserved. Successful gameplay audio scheduling and worker shutdown order remain unchanged.

- Fix CPU shader-interpreter loop nesting and relative addressing used by draw-extent estimation. Each nonempty loop owns one of four fixed slots; empty/full-stack entry does not corrupt depth, and aL reads the innermost live slot. Checked C89 arithmetic preserves the existing signed-step and [-256, 256] address range without allocation or added synchronization. Native packed-microcode regressions fail against the previous implementation. This is a correctness and memory-safety fix, with no measured gameplay speed claim.

- XContent header I/O now uses bounded libretro-common VFS reads and closes every opened header handle on success and failure. Container selection reads only the signature and volume type; initialization fills its existing header directly. This removes the failed-open/successful-initialize handle leaks, two temporary header allocations and redundant full-header reads. Payload mounting and legacy path-typed interfaces remain separate work.

- Vulkan/D3D12 shader binding records use one exact-size C89 owner and borrowed views instead of two final vectors. Native DXIL publication also removes two temporary vectors and compares already-published layouts in place. MSVC x64 shader metadata shrinks by 24 bytes. First publication still allocates; generation serialization and audio scheduling remain.

- Vulkan/D3D12 pipeline workers use direct callbacks with a borrowed owner instead of three std::function wrappers. Requests retain their existing C89 slot and publication lifetime, and worker contexts retain their joined-worker destruction. GNU x64 adapter metadata shrinks from 144 to 80 bytes; synthetic throughput results are mixed and no gameplay gain is established.

- Vulkan and D3D12 retire replaced placeholder pipelines through fixed C89 reservations and a libretro-common MPSC handoff. This removes their retirement mutexes, growing vectors, temporary collection vectors and repeated vector erases. Pool exhaustion selects synchronous creation before shader/layout preparation; it introduces no capacity wait or additional draw-drop policy. Reservations transfer once, GPU completion still gates destruction, and creators join before shutdown releases metadata. Metadata copies do not duplicate reservation ownership. Entry metadata grows by one pointer and the cold pool costs 512 KiB per active backend; gameplay/RSS gains remain unmeasured.

- Shader-cache flush tracking now belongs to the C89 writer's sole producer, removing four backend C++ atomics and redundant dirty resets. Synchronous cache-loading callbacks are borrowed directly, removing two std::function wrappers. Only successfully queued records mark a file dirty; clean submissions enqueue nothing. Vulkan submission maintenance now reaches ordered file flushes and completion-gated placeholder retirement, which had lost their last caller. Maintenance no longer waits for unrelated shader compilation, and the unused startup completion ticket is removed. Existing GPU completion checks, descriptor ownership and audio scheduling remain.

- Shader-cache warmup on Vulkan and D3D12 replaces temporary task/thread vectors, Xenia thread wrappers and C++ work counters with borrowed C89 storage, common atomic claims and libretro-common workers. Small batches avoid redundant worker startup; allocation or partial thread-creation failures retain caller participation. Workers join before storage release or native exception propagation. Vulkan counts completions once per worker rather than once per shader; shader output and audio scheduling are unchanged.

- Vulkan/D3D12 pipeline entries replace C++ atomics with a C89 libretro-common publication record. Concrete placeholder handles remain the basis for draw bindings; packed flags retain independent concurrent updates. D3D12 warm-up failure and pending completion now publish together after the creator's last description read, preventing an old completion from clearing an immediate retry's pending bit. Synchronous warm-up failures also become retryable. Existing shader output, deferred retirement, completion waits and audio cadence remain.

- Removed Vulkan's unused texture/sampler layout UID registry from shader translation. This removes its mutex, hash/collision comparisons, vector/map growth, binding-array copies and per-shader once flag/UID fields. No code consumed these IDs; actual binding metadata, pipeline layouts and shader output are unchanged. This removes avoidable translation work without changing audio or rendering accuracy; gameplay gains are unmeasured.

- Texture invalidation pre-checks use a libretro-common atomic base/mip mask instead of racing plain booleans. Removed the unused cache-wide atomic flag and its exchange on texture requests. Combined pre-checks use one acquire load; existing watch/authoritative reload locking remains. Per-texture size is unchanged in local MSVC/MinGW x64 probes, and the cache object shrinks eight bytes. Rendering conversion and audio behavior are unchanged.

- Scaled two-pass Vulkan resolves no longer request/upload unused native guest-memory backing. Failed scaled destination preparation now rejects the resolve instead of binding native storage to a scaled shader. Both backends use checked destination extents; Vulkan avoids duplicate scaled-residency preparation and widens descriptor-length multiplication to 64 bits. Existing shaders, conversion, barriers and audio timing remain unchanged; gameplay GPU-time gains are unmeasured.

- APU client callbacks and render credits use generation-checked libretro-common atomics in place of per-client callback mutexes and native semaphores. Retiring clients retain borrowed arguments until callbacks finish, then reclaim the driver and guest wrapper before slot reuse. Failed driver creation releases its guest allocation; invalid client indices reject safely. Removed unused partial audio-only state APIs. Existing audio timing/conversion and the shared producer mutex remain; complete libretro savestates are still unfinished.

- Audio queue/driver checkpoints now retain unread PCM, pause/volume bits and native resampler continuation state under exclusive quiescence. Capture borrows up to two SPSC spans without consuming them; restore reuses existing final ring storage, with a copy-free exact-live-view path. Format/phase/alias mismatches, stopped streams and active frontend leases reject. This is component state support; full libretro savestates remain unfinished, and ordinary audio pacing/conversion is unchanged.

- XMA codec format changes now open the replacement before releasing the live decoder. Allocation/open failures retain its configuration and history, and decoding restores input/loop controls instead of consuming the frame. Matching formats keep the allocation-free path. Fault-injection regressions cover cold/warm replacement, guest cursor preservation and successful retry; audio scheduling remains unchanged.

- Decoder-wide raw XMA restore prepares all 320 replacement codecs before changing live state, rejects stale final owners and unsafe PCM aliases, and commits the allocation map, owners and registers only after preflight. Staging uses fixed caller-owned C89 storage, borrows registers/pending PCM and adopts prepared codec backing. No decoding-loop allocation or audio scheduling change is added. Complete libretro savestates remain unfinished.

- Pending XMA PCM now uses the layout of the frame actually decoded, so guest mono/stereo changes cannot select unrelated data or wrap a source offset. Converted PCM uses a fixed C array and no redundant 2 KiB pre-clear. Format-change byte oracles and a controlled negative variant validate the fix; 24 non-silent stream variants remain byte-identical and nine owner snapshot replays pass. Audio scheduling and conversion arithmetic are unchanged.

- Raw XMA capture borrows registers and records all 320 owners with allocation-map agreement, including history/PCM retained by released contexts. Capture requires an active worker to acknowledge its pause; zero-timeout acknowledgment probes no longer read a clock. Added allocation-free quiescent bitmap state I/O, froze the actual cold decoder style and reset stale allocation bits on table rebuild. Native capture/ASan fixtures and bitmap concurrency checks pass. Decoder-wide restore and complete libretro savestates remain unfinished; ordinary audio scheduling is unchanged.

- Launch signature reads now use one checked libretro-common VFS handle instead of stdio, a separate filesystem size lookup and a second open for archive footers. Recognized headers need four logical bytes; footer reads handle short reads and seek errors safely. Removed the unused standalone file-savestate/exit-wait APIs and their partial restore/global pause machinery. Debug guest faults retain logging and fault-thread halting without blocking all workers from an exception callback. Native MSVC, scoped ASan, MinGW classifier fixtures and both full builds pass; full libretro savestates remain unfinished.

- Added exclusive XMA owner checkpoints covering raw codec history, pending PCM and loop/enable/allocation flags. A prepare phase creates the replacement codec without mutating live state; commit adopts it and consumes borrowed PCM before releasing old resources. Unopened owners restore explicitly, malformed inputs and stale stages reject, and discard is idempotent. Real-stream replay, native MSVC and scoped ASan checks pass. Codec allocation is confined to state preparation, and normal audio scheduling is unchanged; complete libretro savestates remain unfinished.

- XMA frame assembly now borrows compressed packet spans instead of clearing and gathering two complete payloads into an intermediate array. Split headers read only their required bytes; the selected frame is copied once to its existing codec-owned packet. Tested MinGW x64 context size falls by 4 KiB including alignment. Offline real-stream PCM is unchanged across 24 ring/refill configurations; C89 bit-oracle and native ASan checks pass. Audio scheduling and required FFmpeg padding are unchanged.

- Added a borrowed raw-XMA history checkpoint for future savestates. Restore validates configuration and both channel spans before copying history into initialized codec storage; opaque FFmpeg pointers are never serialized. This adds no work to normal decode or playback scheduling. Native C89/ASan and MinGW fixtures cover nonzero-overlap continuation and rejected-state nonmutation; full libretro savestates remain unavailable.

- Graphics and APU state pauses now use one reusable C89 controller with borrowed static stage tables, a shared deadline and reverse ownership-aware rollback. A partially failed stage is cleaned up, reentrant transitions fail without blocking, and shutdown can reject new acquisitions without running cleanup on its stopping thread. Native exceptions are contained before the C boundary. CMake uses one C/C++ scalar atomic ABI. Graphics destruction now releases its leaked host register-file mapping. Protocol sanitizer tests, native compilation and a 128-owner OS mapping check pass; complete libretro savestates remain unfinished.

- State-operation graphics pause now quiesces both the vblank interrupt worker and GPU command worker. Pending frontend vblank requests survive pause/resume, and shutdown wakes paused workers before their existing joins. Graphics and APU/XMA pause stages share one timeout budget and preserve pauses they did not acquire when a later stage fails. Graphics vblank anchors and GPU-loss suppression use retro_atomic. Offline C89/MSVC ASan checks pass; this is quiescence groundwork, not complete libretro savestates or a change to normal frame/audio delivery.

- Memory-state restoration validates all nine heap records before changing live RAM. A malformed final heap no longer partially restores earlier heaps. Fixed C89 plans borrow the input metadata and payload; contiguous committed pages use one host commit and direct RAM copy per run rather than one per page. Existing page protections and physical-alias metadata remain. Fixed the Windows host protection query passing a page length instead of its OS result-buffer size. This improves the serialization foundation; libretro savestates are still unavailable pending complete system capture and restore.

- Shader startup completion uses a generation-tagged C89 atomic token instead of a captured callable and completion mutex. Vulkan no longer shares a plain startup boolean between compilation workers and the GPU thread; stale completions cannot clear a newer load. Removed unused completion-callback parameters through both backends' storage APIs. Existing compilation waits, publication order and shutdown joins remain. Native ASan/concurrent ownership fixtures pass; gameplay stutter and GPU-time improvements are unmeasured.

- GPU control requests use a fixed C89 libretro-common MPSC queue instead of an unsynchronized C++ callable queue. Accepted metadata is owned until execution or cancellation; shutdown rejects new requests, joins the worker, then cancels outstanding requests. Ordinary submissions allocate nothing. Capacity is explicit (64 small and four path-sized requests); saturation reports failure rather than dropping work. Removed unused standalone trace playback/reader code while retaining trace capture. Concurrent, cancellation, native exception and MSVC ASan checks pass; no gameplay or GPU-time gain is established.

- GPU trace capture uses owned libretro-common VFS through C89 stream helpers, replacing stdio and local filesystem handling. Header fixups use checked 64-bit positions and transfer failures stop later appends. Trace destruction now closes its file; payload lengths are checked before compression. Gamma ramps borrow two spans instead of allocating a concatenation buffer, with byte-identical compressed output. Removed the uncalled standalone raw EDRAM-file dump API in both backends. Enabled-trace/MSVC ASan and archived-format checks pass; default release tracing stays disabled and no gameplay gain is claimed.

- Vulkan and D3D12 reuse one prepared resolve ownership list for native-scale decisions, direct eligibility and dispatch/fallback. Classification accumulates during the existing fixed-list capture, removing repeated map walks and failed-direct fallback metadata copies. Mixed/layout-mismatched lists remain complete for fallback, and trace dumps still collect fresh data. Actual ownership/fragmentation/overflow fixtures, C89/MSVC ASan classification, native backend syntax and Windows Make checks pass. No GPU command or measured frametime improvement is claimed.

- Vulkan scaled direct resolves reuse immutable whole-buffer descriptors where device bounds permit, removing their transient descriptor allocation/update. Existing C89 planning carries the binding origin through the shader after scaled tiling, with checked unscaled prefix arithmetic. Fallback range views, pixel packing, residency and barriers remain. Actual shader address interpretation, MSVC ASan, Vulkan/DXIL validation and Windows builds pass. The shader gains a constant load/add; GPU-time gains remain unmeasured.

- Vulkan no longer requires a whole 512 MiB shared-memory descriptor for native direct resolves. Checked C89 range planning preserves aligned descriptor bounds and exact tiled destination addresses, allowing eligible constrained-device/pool-failure resolves to skip their EDRAM round trip. Whole-buffer binding, guest residency/watch handling, scaled resolves and shaders retain their paths. Bounds/reference, MSVC ASan, backend syntax and Windows Make checks pass; GPU-time gains remain unmeasured.

- Vulkan and D3D12 direct resolves emit only the destination tiling calculation needed for the dispatch. Shared C89 addressing preserves native Xenos byte offsets, with pixel conversion and loads unchanged. Both dump-pipeline maps become fixed caches, eliminating node/rehash allocation and clearing occupancy after native teardown. This reserves 16,640 bytes per backend and may compile an extra driver pipeline when both destination layouts occur. Native address/cache, sanitizer, shader-validation and Windows build checks pass; GPU-time gains remain unmeasured.

- Vulkan mixed mip chains can keep their large levels on direct image decode. A C89 stored-level partition keeps packed tails intact, decodes each storage region once, and allocates scratch only for the remaining suffix. Original source/decode shaders and array strides remain; source sets are rebound when switching layouts. Atlas, overflow, independent partition/address and sanitizer checks pass. GPU-time and rendered-output gains remain unmeasured.

- Vulkan can decode texture data directly into its integer staging image, skipping the scratch buffer and a second compute pass for eligible 32/64/128-bit host blocks. The C89 SPIR-V rewrite preserves original source/decode instructions and uses checked stored-level atlas bounds for packed mips and arrays. Ineligible layouts/devices retain the existing path. Final image-copy regions now construct directly in deferred replay storage. Offline sink, sanitizer and Vulkan shader validation pass; live rendering/GPU-time gains remain unmeasured.

- Vulkan and D3D12 EDRAM dumps/direct resolves replace runtime source-pitch divide/modulo with a shared exact C89 integer sequence and a CPU-prepared reciprocal. Pixel addressing, fetches, packing and stores remain unchanged. No shader int64, floating-point approximation, GPU branch or extra synchronization is introduced. Offline arithmetic, shader-matrix and validator checks pass; GPU-time gains remain unmeasured.

- Vulkan scaled texture loads reuse cold persistent buffer views on capable devices, removing per-load source descriptor allocations/rewrites and redundant source rebinds. Devices with smaller limits or cold pool failures retain range views. Source offsets and 128-bit tails use checked planning; CPU invalidation/residency remain intact. Scaled loads also avoid an unrelated native-buffer read transition. Native C89/ASan/address checks pass; GPU timing remains unmeasured.

- Reduced duplicate source fetches and packing in Vulkan/D3D12 direct resolves for native-resolution fragments inside scaled output. Eligible 4x runs emit 75% fewer source fetches while keeping the same coordinates, selected samples, stores and conversions. Shared C89 planning adds no runtime storage or GPU branch. Coordinate tests, actual shader matrices, native sanitizers and SPIR-V/Microsoft DXIL validation pass; gameplay/GPU-time gains remain unmeasured.

- Vulkan pending barriers now construct in retained C89 pages and replay borrowed native arrays, removing three vectors and their intermediate copies. Deduplication no longer skips repeated transitions across dependency groups. Existing flush, render-pass and reset lifetimes remain. Page boundaries can add conservative barrier commands, and higher demand can still allocate. Offline native/sanitizer checks pass; GPU and gameplay performance remain unmeasured.

- Removed the D3D12 command processor's growing barrier vector. Barriers construct in their retained replay storage and deferred packets borrow their spans, removing the intermediate array copy. Ordering, cancellation, retry ownership and out-of-submission pending rows are preserved. Pipeline-handle lookup no longer needs a command-processor reference. Native/MSVC ASan and MinGW mock replay checks pass; GPU/frametime gains remain unmeasured, and new high-water pages may still allocate.

- Fixed missing D3D12 ordering between overlapping scaled-resolve UAV writes. A bounded C89 table replaces the unread pending-write flag, keeps the existing state/alias transitions and permits independent footprints without an extra UAV barrier. Footprints include expanded tiled groups and binding-base phase. Offline byte-scoreboard, MSVC/ASan and backend compile checks pass; gameplay/GPU behavior still needs hardware validation.

- Vulkan and D3D12 direct resolves skip fully rejected workgroups outside the destination rectangle, preserving the original shaders and all potentially writing threads. Shared C89 planning avoids allocation and division; actual benefit depends on tile padding. Vulkan scaled direct resolves now publish compute writes across sparse-buffer aliases. Offline equivalence, MSVC/ASan and static Make checks pass; gameplay/GPU timing remains unmeasured.

- Multi-disc playlists now use frontend VFS, reject incomplete reads instead of publishing a partial list, and avoid temporary C++ path/string/vector copies. Multiple guest disc requests are answered in order, including before shutdown joins; callback path bytes survive reentrant edits. The frontend disc module uses C89/common primitives with a retained control lock. Windows rooted joins preserve UNC server names. No gameplay performance improvement is claimed.

- Removed the unused source-expression access-chain engine and high-level constructors from the shader builder, including two stored vectors and redundant adapter state clears. Raw SPIR-V access chains, direct swizzles and explicit memory operands are preserved. Builder objects shrink by 88 bytes on measured GCC x64; offline geometry generation is modestly faster, while helper/guest shader bytes and tracked allocation counts remain unchanged.

- Replaced shader-block successor vectors with C89 arrays in the existing reusable payload arena. Traversal borrows indexed spans, latest growth can stay in place, and failed growth preserves prior edges. This removes per-block edge heap allocations while keeping edge order, shader bytes and block size unchanged. Added C89 fault/reuse tests and ASan checks for expired views; larger modules can still grow retained pages.

- Shader blocks no longer build unused predecessor vectors. Forward control-flow traversal and branch output stay the same, while reverse-edge allocations/copies disappear and measured x64 blocks shrink from 136 to 112 bytes. Helper/guest binary comparisons and native sanitizer checks pass. Corrected the optional profiling harness to keep allocator cleanup and baseline arena configuration consistent.

- Resolve watch rearming in Vulkan and D3D12 now uses two fixed page bitmaps instead of growing range vectors. Submission detaches a borrowed bitmap without copying; concurrent faults queue into the other. Adjacent/overlapping pages coalesce, reducing repeated memory-watch calls while preserving coverage across all physical aliases. This reserves about 32 KiB and adds bitmap work for sparse batches; required fault serialization remains.

- Vulkan and D3D12 recent-read history now uses fixed C89 storage instead of a second node map. Exact keys, 60-frame expiry, full-map clearing and frame-counter wrap retain their previous behavior. Tracking no longer allocates nodes during play; it reserves about 97 KiB even with few reads. This GPU-thread history remains separate from fault-owner lifetimes.

- Vulkan and D3D12 resolve ownership now use fixed C89 rows and a bounded hash index, removing owner-node/rehash allocations and the temporary pruning-age vector. Surviving fault-owner views stay stable while index links move; exact eviction and frame-wrap semantics match the legacy reference. This reserves about 209 KiB per processor even at low occupancy. Windows builds, MSVC ASan and reference fixtures pass; CPU traces improve, while gameplay gains remain unmeasured.

- Fixed Soulcalibur IV startup: XEX loading now accepts omitted tails of explicitly discardable PE sections and clips their resident snapshots, while retaining bounds checks for ordinary sections and guest-address overflow. Failed launches use the normal teardown path so stale input/graphics pointers cannot crash the next retro_run. Added the exact section-layout regression to Linux/Windows CI, plus an offline failed-launch callback test.

- Resolve fault readback now captures final Vulkan copy records or compact D3D12 ranges directly into cold-reserved C89 storage, removing CPU metadata growth, relocation and the intermediate Vulkan range vector. Page-owner keys use libretro-common atomics, and access bounds clamp before addition to prevent wrap. Clipping, packed delivery and native ordering remain unchanged. CPU/reference, sanitizer and concurrency checks pass, including TSan; cold capacity increases for small workloads, and native staging/driver allocations remain.

- D3D12 derives system constants directly into two inline CPU snapshots and swaps pointers on change, removing its vector shadow and duplicate 688-byte copy. Frame invalidation, failed-upload retries and required GPU upload copies are preserved. This trades bounded extra CPU storage for no shadow allocation; changed-draw CPU fixtures improve, while some rarely-changing GCC cases are slightly slower. No gameplay gain is claimed.

- Vulkan deferred recording now uses reusable C89 pages instead of a growing vector. This removes packet zero-filling and relocation copies during growth, keeps earlier argument views stable, and retains warmed storage across reset. Native command ordering is unchanged. CPU fixtures improve on MSVC, MinGW and GCC; page slack can increase retained memory and new peaks still allocate. GPU/gameplay performance remains unmeasured.

- Memexport tracking now marks and clears bitmap words in C89 and borrows copy runs instead of allocating per-backend vectors. Vulkan counts runs with word operations and fills final native copy records directly, removing its intermediate region vector and memcpy. D3D12 emits runs in one pass. Exact copy/barrier bounds and existing fence/readback ordering are preserved; native command-storage growth still allocates at new peaks.

- Shared-memory upload generation now writes directly into cold-allocated C89 storage sized from the guest page aperture. Fixed the valid 65,536-range boundary, removed undefined wide shifts and the remaining FixedVMemVector template, and bounded partial bitmap refreshes. Validity readers and all writers now use libretro-common atomics while preserving required watch synchronization and native GPU ordering. Range-record storage no longer grows during play; refresh helpers may still allocate. Offline fixtures and builds pass, while TSan could not start on this host.

- Vulkan and D3D12 CPU-upload filtering now borrow and compact the producer's C89 range records, removing two duplicate vectors and their growth allocations. Unchanged lists are not copied; mixed lists move only surviving records after a removed range. GPU memexport refresh, validity updates, native payload copies and barriers keep their ordering. Offline selection and build checks pass; no gameplay performance claim is made.

- D3D12 deferred recording now checks packet sizes and grows with reusable C89 pages instead of relying on a release-disabled assertion around a fixed 8 MiB buffer. Larger submissions keep prior command views stable without copying recorded packets; warmed pages survive reset. Removed four unused descriptor snapshot vectors and their layout IDs. New peaks still allocate, and CPU fixtures show some cost for the added bounds checks; no gameplay speedup is claimed.

- D3D12 bindless descriptor reuse replaces its free vector and pending deque with fixed C89 index links and batches attached to existing command allocators. Completed transient batches splice into reusable storage without copying their indices or allocating separate index metadata. Bounds and duplicate releases are checked, and CPU ownership is reserved before native allocator creation. This trades a cold 1 MiB reservation for reduced hot allocation; transient/mixed CPU fixtures improve, while persistent-only loops remain slower. Existing command-allocator growth, GPU lifetime and audio pacing are unchanged.

- Vulkan texture descriptor reuse replaces its deque and layout-keyed free vectors with shared C89 records. Completed key/frame batches retire by splice, preserving exact per-layout handle order without per-handle copies or hash lookups. Native completion checks and reset boundaries are unchanged. Offline compiler benchmarks improve; retained metadata can be larger on GNU, and new peaks still allocate.

- Vulkan descriptor budgets now use borrowed C89 request plans and count-only mutable storage. Removed duplicate descriptor-type IDs and their initialization copies, halving counter payload and saving 1,536 bytes across the four warmed owner pools on tested x64 builds. Native allocation traces and failure cleanup remain unchanged; paired CPU fixtures improve on GCC/MinGW/MSVC. Gameplay gains are unmeasured.

- Vulkan descriptor-pool search now uses retained C89 nodes instead of a multimap and copied page values. Switching active pages moves pointers, and insertion/removal no longer allocates. Native selection order and failure-safe ownership are preserved. Mixed-search CPU fixtures improve on GCC/MinGW/MSVC; hot-page results vary slightly. New metadata peaks and native pools still allocate.

- Vulkan descriptor-pool counters now borrow stable spans from retained C89 ownership pages, removing a separate heap array for each pool. A paired failure-injection workload drops 805 C++ allocations while preserving the native allocation trace. Search-map and new high-water allocations remain; retained counter capacity can use more idle metadata.

- Fixed a Vulkan descriptor-pool ownership leak when a C++ allocation fails after native pool creation. A retained C89 registry reserves ownership before creation, removes the full-pool vector and releases every pool at the existing reset boundary. Failure-injection fixtures reproduce the old leak and pass with the fix. Static descriptor-size tables are borrowed directly instead of allocated and copied. Search-map allocations remain.

- Vulkan sparse binds now go directly into retained C89 storage with stable borrowed views for submission. Removed three vectors, stack-bind copies and submission-time record rebuilding while preserving queue/semaphore ordering. New high-water growth can still allocate; offline checks do not certify gameplay gains.

- Vulkan descriptor reuse now retires completed frame batches by list splice instead of walking every handle. Per-handle records shrink from 24 to 16 bytes on tested 64-bit builds; the benchmark's warmed metadata request falls from 9,432 to 7,320 bytes including owners. Lease cancellation, exact free-list order and existing completion thresholds are preserved. No GPU/gameplay performance claim is made.

- Vulkan single-layout and constant descriptor reuse replaces three free-list vectors and two pending deques with stable C89 records. Pending handles become reusable only after the existing completed-frame check; context setup warms metadata and pool resets retain its capacity. Native allocation failures and C++ exceptions release metadata leases safely. CPU metadata benchmarks improve on tested GCC/MinGW/MSVC builds; no gameplay speedup is claimed.

- Vulkan descriptor image scratch now uses checked C89 storage and fills final Vulkan records once, preserving every API field while removing the vector and redundant initialization stores. Both renderers publish resolve-submission indices through libretro-common release/acquire operations without changing GPU completion waits. D3D12's one-shot PIX capture flag also uses common atomics. Storage growth still allocates; CPU fixtures and builds do not certify gameplay performance.

- Vulkan draw sampler snapshots now use reusable C89 storage with an index-only commit, removing four vectors and full-list snapshot copies. Overflow retries and repeated binding updates retain current records; texture-cache sampler ownership is unchanged. Async publication cannot expose more sampler descriptors than were collected for the draw. Removed two unused D3D12 sampler vectors. New high-water peaks still allocate; no gameplay performance gain is claimed.

- Mapped instruction facts now use libretro-common atomic word reads and explicit C89 masks throughout the CPU callers, replacing concurrent C++ bitfield reads and temporary mask copies. Tested GCC/MSVC C and C++ layouts match the existing version-4 cache words. Concurrent updates, mapped-file persistence and loader regressions are checked offline; no gameplay performance claim is made.

- Instruction-cache preparation now uses checked libretro-common native VFS operations instead of std::filesystem I/O. Valid caches keep their flags; invalid sizes/versions rebuild zero backing, with only the fixed header touched after mapping. Failed reads do not authorize repair, and file errors disable this optional cache. Lookups reject the exclusive code endpoint, truncated words and unloaded modules. Writable flags remain mapped without a staging copy; no gameplay speedup is claimed.

- PE section discovery now checks DOS/NT/optional headers, complete table bounds and resident section spans using byte reads. Reusable C89 storage replaces the section vector and preserves owned snapshots across guest header changes. Repeated parsing reuses capacity, malformed input publishes no sections, and unload hides old records. Failed PE continuations remain failures on retry, and empty executable ranges skip preanalysis before reserve-size underflow. Imports and other PE directories remain separate work.

- XEX delta patches now use bounded borrowed packet spans and verify the complete image hash chain before relocating or modifying the guest image. Invalid ranges and truncated blocks return errors. Encrypted patch scratch avoids zero-initialization immediately overwritten by decryption; synchronous LZX calls remove three wrapper allocations. Real synthetic plaintext/encrypted patches and normal compressed-image loading are checked offline. Decoder allocations remain, and patch application is not fully transactional.

- XEX loading now uses owned reusable C89 storage for headers and patch data. Encrypted normal-compression images use one decrypt/compaction workspace across key retries instead of two full-size buffers; plain chunks borrow input directly. Added bounded header/security/table checks, SHA1 block-chain parsing and in-place-safe CBC. Plain and basic images avoid zeroing bytes immediately overwritten; holes and padding retain their previous zero-fill semantics. Six synthetic compression/encryption cases match all guest bytes offline. PE/import parsing, legacy delta patch paths and heap-reset ownership still require further work.

- ELF loading now validates borrowed PPC wire records before guest writes, merges shared heap pages with an allocation-free linear cursor, and rolls back newly reserved pages on failure. It copies file bytes directly and zeros only BSS, removes the retained header vector, and initializes load/entry state. Initial libxenon loads explicitly reuse verified boot backing; unrelated allocations remain protected. PT_DYNAMIC is treated as metadata rather than an independent load segment. No gameplay speedup is claimed.

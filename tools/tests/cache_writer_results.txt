Cache-writer ownership and Vulkan maintenance (0173)
===================================================
The actual ConfigurePipeline call sites enqueue persistence records only from
the GPU command processor (or its quiescent lifecycle owner). Background pipeline
creation publishes native handles; it is not an extra cache-writer producer.
EndSubmission shares that same exclusive producer ownership. Four backend
std::atomic<bool> flush flags and their duplicated resets are therefore removed,
not replaced by an atomic wrapper. C89 queue publication marks plain producer
bits only for successful nonempty shader/pipeline records. Dirty metadata is
separated from the consumer's immutable sink/stride fields by128 bytes. Flush
requests coalesce those bits into one ordered empty barrier, retain them if
publication fails, and do nothing when clean. Full queues still backpressure.

ShaderStorageWriter loading callbacks are now borrowed native callables for the
synchronous initialization only, removing two std::function wrappers. All actual
callers provide both callbacks; translation joins its bulk workers before
returning. No callback escapes into the file worker. Existing microcode borrows,
queue-owned descriptor copies, hashes, endianness and file formats remain.

Source audit found VulkanPipelineCache::EndSubmission had no remaining caller.
Its file-flush and completed-placeholder retirement work consequently wasn't
being driven during normal submissions. VulkanCommandProcessor now calls it
after a submission closes. The cache method does not drain compilation, call a
GPU wait or wake idle compiler workers: requests already wake them on publish.
The unused startup completion ticket and its registration are removed. Draw/query
paths still await concrete dependencies. Existing retirement compares each
recorded submission with GetCompletedSubmission; future/in-flight handles stay
retained. It runs on the GPU owner, after deferred commands have been replayed
and submitted. The next BeginSubmission resets CPU pipeline binding snapshots.
Existing shutdown still joins creators before force retirement and shader release.
The retirement mutex, persistent vector and temporary collection vector remain;
allocation-free retirement and measured gameplay/RSS improvement are not claimed.

No frontend, actual Vulkan API destruction, game or JIT execution was performed
for this optimization. Wiring of live maintenance is compiled/source-audited;
its impact on live driver memory/frametimes remains unmeasured. Remote Linux/ARM
CI added or extended, not run locally. Installed RetroArch core is unchanged.

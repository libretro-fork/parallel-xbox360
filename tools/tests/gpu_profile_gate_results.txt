Vulkan host GPU profiling gate: focused validation, 2026-11-08

Change scope
Runtime changes are confined to VulkanCommandProcessor .cc/.h (20 insertions).
Header explicitly includes xenia/base/profiling.h, providing its default macro.
XE_OPTION_PROFILING now gates profiler-only class storage/helpers, timestamp pool
creation/destruction, collection, command reset and two timestamps per submission,
profiler counter windows, render-pass profiler increments and missing-slot warning.
No guest query logic, command submission/queue completion, fences, synchronization,
resolve, shader, draw or presentation semantics were edited. Profiler-enabled code
inside the new guards is unchanged. No new logging, waits, locks or dependencies.

Reason
Default XENIA_ENABLE_PROFILER=OFF compiles COUNT_profile_set to no-op but previously
retained host timestamp work and private counters. This change removes discarded
work from that configuration. It is not evidence that this overhead causes DS2's
4x resolution GPU load, and no speedup or memory reduction was measured in-game.

Limits
------

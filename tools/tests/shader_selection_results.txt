MIN/MAX selected bits, CPU throughput and shader compiler gates (2026-11-16)
=========================================================================
Parent: 8fd7ca98e7945a40de49e11bbd3ba72757780d07.

The CPU source loader flushed subnormal values before MIN/MAX, and the generic
SPIR-V helper rebuilt its selected value from flushed comparison magnitudes.
Both lost bits that the specialized shader retains. Compare denormal magnitudes
as zero, but return the original selected modified word. MAX chooses A on ties;
MIN chooses B; unordered comparisons choose B. Keep ordinary arithmetic source
flushing unchanged. Vector MAXA uses the same selected-value repair while its
address calculation retains the existing GuestAdd/clamp path.

New runtime algorithms are MSVC C89 helpers. SSE2 operates directly on existing
four-lane operands using integer masks/comparisons and an unaligned final store.
No temporary SIMD buffer, register-bank snapshot, heap allocation, lock, clock,
logging or synchronization is introduced. The fallback uses the same scalar bit
rules. MAX/MIN scalar history retains selected bits even without a destination.
The generic integer helper drops two reconstruction operations (ten words):
control 10525->10515, continuation 13736->13726. Both retain the 16384-word reserve,
one cold allocation and 1000 allocation-free same-owner rebuilds. The two older
arithmetic/program modules remain byte-identical within each tested compiler.

 Each draw checks all three captured vertices and feedback redzones. Native

Throughput and compiler cost:
CPU profiling creates the typed owner once and initializes code/constants/temps
outside each interval. A C89 loop executes one million actual interpreter programs
per case; 12 cases cover vector/scalar MIN/MAX with constant/temp sources plus
ADD/MUL controls. Both revisions must produce identical finite words before and
after timing. No old incorrect subnormal result is used as a valid speed oracle.
Two orders of seven alternating pairs pass the existing 10%/2ms median, 25%/5ms
p95 and 50%/10ms maximum gates. Vector ratios are .9106.. .9427; scalar selection
ratios 1.0376..1.0416. ADD/MUL controls range .9997..1.0359. These are measured CPU
component costs, not a gameplay improvement. Initial scalar-only correction showed
an 8..10% vector cost increase; it was retained as evidence and replaced by SSE2.

The component CPU harness uses freshly compiled per-revision Release interpreter
objects and identical frozen Release dependencies. Memory/RegisterFile/interpreter
header ABIs are unchanged from those dependencies to the parent; setup remains
outside measurement. The first attempted ASan/Release annotation mix failed to
link and was not timed. Full CI instead builds each actual revision normally.
An initial 100k-loop screen is retained; final million-loop runs keep all eight
selection cases and add four arithmetic controls for better timing resolution.

Module and primed-PSO compiler profiles use seven alternating pairs in both
orders on 5090 and llvmpipe. All four cohorts pass unchanged limits. Warm PSO median
milliseconds: NV .0124->.0125 / .0114->.0120; software 19.627884->20.016620 /

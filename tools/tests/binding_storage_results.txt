Immutable shader binding storage (0176)
=======================================
SpirvShader now owns one exact-size C89 allocation for four-byte texture and
sampler records. Both native renderers borrow const spans over that storage;
views carry pointer/count metadata only, never copy binding payloads. Vulkan
translation packs its final records directly there. Native DXIL publication
packs directly into the same final storage on first publication, then compares
subsequent layouts in place. Two final std::vectors and the two temporary DXIL
publication vectors are removed. No fixed maximum-size table is embedded in
every shader.

On MSVC x64, sizeof(SpirvShader) changes from 600 to 576 bytes. Both packed native
record types remain four bytes. A shader using both record kinds needs one
payload allocation instead of two; empty bindings allocate nothing. Repeated
native publication allocates no new binding records and preserves borrowed
addresses. One allocation on a shader's first publication remains; this is not
a guarantee of allocation-free gameplay. Translator scratch vectors and the
shader-generation mutex remain. That mutex still serializes concurrent variants
through generation and publication; it has not been disguised as a spin lock.

Readiness publication remains release/acquire. Draw code forms spans only after
the readiness check, since constructing a span reads its counts. Allocation
failure leaves the C89 owner unchanged; SPIR-V publication invalidates that
translation without marking the bindings initialized, allowing later retry.
Readers must finish before shader destruction. The C89 owner frees the single
allocation during the same shader-destruction lifetime as the previous vectors.
Native bitfield enum/object lifetime conversion remains minimal C++ ABI glue.

Shader control-flow lowering / unreachable SPIR-V references (0186, 2026-11-08)
Parent: 0998905aeb66456048027ce9f79e7a0ddbdf712f

Changes
-------
- Native DXIL forward jumps directly target reserved CF blocks after committing
  ALU state. Next-instruction jumps skip their irrelevant condition read. Only
  backward/self jumps, loops and calls require the dominating PC dispatcher.
  Between dispatcher entries the direct edges strictly increase CF index.
- Allocate loop slots only with loops, call slots/depth only with calls and PC
  only with a dispatcher. Return without any call falls through. Calls to the
  next instruction retain two executions (subroutine then return continuation).
- Vulkan next-instruction jumps do not create labels/read unused bool constants;
  genuine shared/backward labels retain the existing NVIDIA switch workaround.
- Prewalk the existing borrowed block-emission plan before both size/output
  passes. Two unused packet flag bits mark local/emitted records without new
  instruction storage. Omitted blocks' phi inputs, names and decorations are
  filtered consistently. C89 phi emission borrows immutable original words;
  no temporary operand buffer, payload mutation or new lock is introduced.

Limits
------
Vulkan fixture output is validated but not physically GPU-executed here.
At0186, Vulkan's missing ProcessCallInstruction/ProcessReturnInstruction overrides
were an existing limitation (implemented later in0188); call-to-next tests assert Vulkan label retention and
CPU semantics, NOT correct SPIR-V subroutine execution. Native DXIL subroutine
execution is tested. Shader-arena orphan records survive until owner reset;
this does not eliminate every shader allocation. Prewalking and liveness scans
have CPU cost; shader compilation throughput/FPS/spills are not measured.
No game launch, installed DLL replacement, audio scheduling, guest query,
queue synchronization or frontend pacing change is part of this patch.

SPIR-V operand construction experiment, 4 November 2026
Host: AMD Ryzen 9 9950X3D, Windows x64. Single-threaded, no affinity pin.
Baseline: 7e088a41 spvIR.h. Same fixture and compiler flags for both versions.
Five batches of 200000 stack Instruction objects per case; append mixed ID and
immediate operands, dump to an already reserved output vector, checksum words.
Two runs in opposite executable order; no core builds running while measuring.
This measures synthetic operand construction/serialization, not whole-shader compilation or FPS. The timed Instruction objects are storage probes, not GPU-executable programs.
Instruction heap allocation, block/module containers and output growth are not
removed by this change. More than four operands can still allocate/grow.

Plain timing uses ordinary C/CRT allocators with allocation tracking disabled.
Tracked runs override C++ new/delete and the C operand allocator to count calls.
The shared report's bytes field is operand count, live is sizeof(Instruction),
and workers=0. These fields are NOT RSS or retained/peak heap measurements.

Checksums match every baseline/current pair, including the zero-operand control.
Zero-operand controls include small regressions; no improvement is claimed there.

Reproduce GNU/MinGW builds with tools/tests/run_spv_operands_bench.sh.
BASELINE_COMMIT selects another baseline, TEST_BUILD_DIR selects output,
BUILD_ONLY=1 builds without timing (finish other CPU-heavy jobs before running).
The fixture also builds with native MSVC after compiling the C profile and
operand .c with /TC /MD /O2. Baseline include overlay must precede src; both use
identical fixture flags. Define XE_SPV_BENCH_PLAIN and compile operand storage
without XE_SPV_ALLOC/XE_SPV_FREE overrides for uninstrumented measurements.
Heap flags stay bit-packed: capacity*4 + ceil(capacity/8) payload bytes, not one byte per flag. Inline flags use four bytes. No release instrumentation or diagnostic counters are introduced.

Separate production-builder regression: five compute modules (arrays of 1,4,8,33,129 floats with arithmetic/store/return) match baseline binary output exactly on MinGW and Linux ASan/UBSan. All five MinGW outputs also pass spirv-val --target-env vulkan1.1. Run tools/tests/run_spv_module_compare.sh; optionally set SANITIZER and SPIRV_VALIDATOR.

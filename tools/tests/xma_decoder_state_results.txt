All-slot raw XMA capture and transactional restore (0163/0164)
===============================================================
XmaDecoder::CaptureState covers 320 modern/raw owners, not just allocated slots.
The caller supplies fixed/reusable xe_xma_decoder_view storage; no large local
register/owner array is placed on the worker stack. The 64 KiB register file,
codec history and pending PCM are borrowed; allocation words and small owner
metadata are written directly into the caller's view. Capture allocates nothing.
Views expire at mutation/destruction and are native views, NOT wire records.
Failed capture clears version; a partially filled output must never be consumed.

C89 structural checks validate count/mode/base range, register span shape, owner
slot IDs/guest addresses, basic owner layout and allocation-map agreement. A set
bitmap bit means free; slot zero is the high bit. These checks are NOT complete
codec-payload validation. Decoder-wide PrepareState performs full candidate
preparation/validation before any live commit.

The actual context style is frozen once by the cold factory and recorded in the
owner. Capture never reads a mutable config string to decide a derived-type cast.
Fake/master/old captures reject before a raw-context cast. All styles retain
existing playback implementations. Duplicate setup rejects before replacing an
owned table. New context tables reset retained bitmap words, rather than leaving
old occupied bits attached to freshly unallocated objects. The exited synchronous
worker clears worker_running_; running asynchronous capture requires an actual
current-generation pause acknowledgment and zero pending work. Every synchronous
guest/control caller must ALSO be quiescent externally; this does not freeze CPUs.

Zero-timeout xe_pause_gate_wait_workers is now a pure atomic acknowledgment
probe without clock/event waits. Positive bounded waits keep their existing host
monotonic timeout. No new clock, lock, buffer or work is added to normal decoding.
FFmpeg decode arithmetic, stable-format delivery and audio scheduling are unchanged.

Pending PCM source-layout safety and redundant-clear removal
------------------------------------------------------------
Consume formerly calculated source offsets from the guest's current is_stereo
bit. Switching mono/stereo while a decoded frame remained could select unused
bytes; stereo-to-mono with five blocks pending formed a negative index, which
could wrap when multiplied by the unsigned 256-byte block size. The decoded
frame's total block count is now frozen at successful conversion, preserved by
pending drain and reconstructed from codec profile at owner restore. Invalid
private counts reject before a source pointer is formed and cannot spin Work.
Loop truncation uses that same frame origin. This is internal source-span safety;
it is not a claim of silicon validation for every mid-frame register change.

Only the remaining decoded interval can now be read, so borrowing precisely that
interval for snapshots is valid even when guest channel settings change. The
raw PCM owner uses a fixed C byte array, and conversion overwrites the complete
1024/2048-byte mono/stereo frame on success. Removed its unconditional 2048-byte
pre-clear; decode failure publishes no pending PCM. Codec padding still clears
as required and conversion/guest-ring copies remain. No new payload copy or
allocation is introduced. This removes logical zero stores, not a measured
DRAM-bandwidth or gameplay/FPS improvement.

A source-byte oracle seeds distinct 256-byte blocks in actual decoded frame
storage, first verifies conversion fully overwrites a poisoned frame span, changes guest layout with pending PCM, then requires the correct old
frame block on both mono-to-stereo and stereo-to-mono drains. A controlled native
variant restoring the legacy guest-layout calculation fails at that byte oracle
(exit 1), while production passes. The test does not execute the original unsafe
wrapped-address read. A real coefficient-bearing Title_Call stream still emits
770048 bytes with SHA256
463708c0b7acfc6c013a018691d8429bfd93b0de3b90469dcf2851f00851469c across all 24
ring/refill variants, identical to the pre-change reference. Nine owner replays,
including five partial-PCM checkpoints and unopened-phase restoration, still pass.
The layout byte occupies former padding: MinGW owner size 2240 -> 2240 bytes,
MSVC 2368 -> 2368. These are object-size checks, not RSS measurements.

Quiescent bitmap capture/restore uses exact native 64-bit words and validates
byte count, storage shape, pointer wrap and overlap with atomic cells or owner metadata before mutation. Unaligned
external storage is accepted through memcpy; no alias of atomic cells or second
bitmap allocation is used. Restore performs common atomic stores and requires
quiescent users; it is NOT a concurrent whole-map transaction or a portable wire
format. The supported scalar atomic word ABI is checked at compile time.

Decoder-wide raw transaction (0164 work):
PrepareState creates 320 replacement codec resources before live mutation; a late
FFmpeg checkpoint failure discards the entire prepared prefix. CanCommitState
preflights every owner/candidate/previous identity, root layout, register mapping,
allocation-bit agreement and known mutable-storage aliases under exclusive
quiescence. Commit validates the bitmap before its first store, applies the
already-preflighted owner transitions with no fallible calls, and copies registers
only when the source is external. No observer may run during these steps.
The fixed caller-owned C89 stage is a native resource owner, never copied or
serialized and never placed on a small worker stack. Register/PCM input remains
borrowed and immutable until commit/discard, except an owner's own PCM may restore
in place with memmove. Cross-owner PCM aliases and register aliases into owner
objects are rejected. Arbitrary pointer provenance is a caller obligation: these
are native views, not an untrusted-pointer wire parser. Discard is idempotent for
valid stages and must precede decoder destruction. Codec resource allocation is
confined to explicit state preparation, not normal decode or commit. Guest RAM
and the rest of the emulated system must be restored by the future orchestrator.

Codec reconfiguration failure safety (0165 work):
Ordinary PrepareDecoder now opens a candidate before publishing it and releasing
the previous codec. Null allocation and failed open return failure without live
mutation. Setup's zero profile and validated restore candidates keep the published
codec either canonical cold or successfully opened. Matching profiles reuse it
with only the existing profile comparisons; no extra per-frame codec-open query.
Decode retains the original setup point after packet validation. Only a profile change saves two scalar rollback words (8 bytes), covering input cursor/valid bits/current buffer/loop count/private loop-start flag. Failed preparation restores those controls and returns without a guest error or invented silence. Matching formats take no context snapshot and no PrepareDecoder call. Invalid packets cannot reconfigure the codec and lose its overlap history. Resource setup may transiently retain one old
and one new codec for the one owner being reconfigured. No normal queue/pacing,
conversion arithmetic or callback policy is changed.
The C89 driver uses real FFmpeg av_max_alloc only in its isolated offline process.
Limit 1 rejects context/private-state allocation. For open failure, an optional test-only recompile redirects this translation unit's avcodec_open2 call to a fixture adapter. After actual candidate creation, the adapter limits allocations to 1 for the real FFmpeg open call, then resets the limit; a hit counter proves that path ran. Production builds have no adapter, flag, counter or injection branch. Test cases require
cold/warm live identity/config/history preservation, matching-format reuse under
allocation failure, unchanged 64-byte guest context after failed decode kicks,
and successful later retry producing stereo PCM. Limits are reset to INT_MAX
before any unrelated fixture work. This is targeted allocation-failure coverage,
not a claim of whole-core OOM recovery or silicon timing validation.

Live-component texture format conversion (0191,2026-11-08)
Parent3deb915fa

Mechanism
---------
After signedness/swizzle handling, the old conversion always constructed and
processed float4 even when the guest fetch consumed only one component.
The C89 lane plan records ascending original component indices in four fixed
slots. It does not copy sample payloads, clear unused slots, allocate storage
or own the caller's values. Invalid/empty masks are rejected before indexing.

Typed SPIR-V glue selects existing SSA IDs and the matching scalar/vector types.
Packed width/sign fields retain ORIGINAL component offsets, including masks
with gaps such as G/A. Componentwise math and uniform branch predicates retain
their order. Scalar scaling uses FMul; vectors retain VectorTimesScalar.
Only selected borrowed result IDs are updated. There are no new runtime payload
buffers, texture samples, transfers or synchronization operations. Existing IR
records/constants can still allocate through the builder's owned storage.
Cache modification26 rebuilds old compiled shader/pipeline output once.

Focused verification
--------------------
C89 planner: all masks0-255, a high-bit invalid mask, NULL output, ascending
indices and exact recovery of the mask. MSVC/GNU pass; WSL GCC ASan/UBSan with
leak detection passes.

Thirty fixtures call the PRODUCTION conversion helper: masks1-15, both point
conversion eligibility settings. The C89 structural scanner checks that EVERY
floating arithmetic/extended result has exactly the live width. All thirty
modules pass spirv-val targeting Vulkan1.1.

The C89 Vulkan runner performs23040 GPU differential cases/92160 lane checks:
all masks, all16 encoded width fields, all four sign fields, normalized/integer
conversion, point-conversion policy/flags and three finite input patterns.
Different channels have different fields/values to expose incorrect packing.
Live outputs must match full-width conversion bit-for-bit; inactive outputs
must preserve original input bits.4080 bytes after each16-byte output remain
untouched. A separate scalar C89 model checks numeric results for all lanes,
admitting either zero sign; the GPU differential still requires exact zero bits.
Independent bypass and4-bit point-reconstruction goldens are also checked.
These test decoded-value CONVERSION, not full texture sampling/coordinate decode
or every guest format/float mode. No game or frontend process is started.

Parent control: the original conversion block is extracted and compared exactly
with Git3deb915fa, then emitted in the same typed fixture envelope. Its original
four-lane math supplies the two full-width reference modules. The candidate
also passes all23040 GPU differentials against these parent-block modules.
This is a captured parent conversion block, not a complete parent core build.
Those private controls/game data are not shipped in this patch.

Negative control: change the G/A module's packed-field offset vector from[6,18]
to[6,6]. SPIR-V remains valid, but the GPU check rejects mask10, proving that
the tests detect selecting the wrong original component field.

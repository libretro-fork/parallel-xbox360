Prepared resolve ownership (0152)
================================
Vulkan and D3D12 previously walked ownership for native-scale classification,
again for fast-copy eligibility, and again when collecting direct-dispatch
rectangles. A direct preflight failure then collected the same rows for fallback.
Converting paths could also repeat the native-only and dump walks.

Resolve now captures into the existing cold fixed worklist once, accumulating
both existing C89 scan flags in its native record adapter. required=0 ensures
classification does not early-stop capture on mixed scale or layout mismatch.
Native selection, eligibility and direct/fallback dispatch borrow the captured
rows. No second metadata list or global snapshot cache, epoch, mutex, atomic,
allocation or release profiling counter is added. Failed-direct fallback no
longer recopies the rectangle metadata. Successful direct and ordinary fallback
still copy each stack-produced row once into its necessary owned lifetime.

This is GPU-command-processor-owned storage, scoped to the current Resolve
copy. Existing code does not mutate ownership between capture and dispatch;
native-scale info recalculation was already based on that same EDRAM tile span.
No borrowed row may outlive its worklist reset. Whole-aperture trace downloads
use the default fresh collection path. Overflow fails the Resolve before GPU
copy work; a partial list is not dispatched. Empty, partially-owned, mismatched
or converting resolves keep their original fallback decisions. No changes to
pixel shaders, conversion precision, barriers, native descriptor lifetime,
mark-resolved, clears or content-close joins.

Costs: classification now accumulates all rows even if an individual old query
could stop early. Paths previously needing only one walk also accumulate flags;
there is no universal timing improvement claim. Worklist capacity/CPU storage
remain unchanged; scan/capture context adds bounded stack state. Driver and
other runtime allocations remain. No end-to-end zero-copy claim.

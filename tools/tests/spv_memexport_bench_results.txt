Direct memory-export mask loops, 2026-11-06
Parent: 76d1102c0321f4597e7a87c1e0dec981eaf2d364.

Remove the two nested std::function<void(uint32_t)> helpers in the actual
SpirvShaderTranslator::ExportToMemory path. Replace all 29 ordinary and five
guarded-store callback sites with direct loops using a C89 least-set-bit
iterator. Iteration keeps only a scalar remaining mask and index, rather than
copying a callable or materializing an index list. Selected registers retain
ascending order. Original body scopes, including local destruction before the
guard's makeEndIf(), are preserved. Packing/NaN/rounding/store expressions are
unchanged. No generic C++ callback wrapper or owning replacement is introduced.

The C89 iterator reuses libretro-common compat_ctz, guards the zero input before
the intrinsic and clears the least set bit with value & (value - 1). It supports
all 32 bits; the guest decoder restricts this generator to the five hardware
export registers. No allocator, global state, copied payload or staging array.
Other C++ arrays and translation allocations remain.

The new actual-microcode fixture found a pre-existing crash before runtime code
was edited. Pixel memory export at resolution scale 2x3, host-RT mode, with no
color output could use input_fragment_coordinates_ == NoResult. Offline GDB
traced the resulting null record to createAccessChainView's base=0 in the center
host-pixel guard. The existing guard already needs FragCoord regardless of color
output; the interface declaration now includes supported scaled memory export.
Depth-only helper paths are short-circuited before accessing a current shader.
The fix adds an input where the previous build crashed, not a new resampling or
memory-export algorithm. No frontend/game/GPU process was started.

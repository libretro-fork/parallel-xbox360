Raw packed control-flow interpreter foundation (2026-11-10)
==========================================================
First parent: d0720caa9815b3e67e467c530346c53ed0ce629f.

xe_alu_control_spv_build emits one fixed SPIR-V1.0 compute module,6770 words,
with Shader capability,32-bit integer types, three functions and three structured
loops. It imports no GLSL instruction set and uses no GLSL parser, float/64-bit
shader types, per-program code generation or second module allocation.
The earlier arithmetic2875-word and EXEC_END6171-word entries remain available.
Sequencing predicate-emitter side effects explicitly retains byte-identical
original modules on the measured MSVC toolchain; arbitrary host argument-order
choices are not part of the portable semantic contract.

The control entry consumes the existing8-word descriptor ABI. Shared immutable
packed code and constants remain borrowed through GPU completion; endian
correction is performed by loads, with no host-normalized program copy. One
invocation keeps private registers, scalar history and position state across
multiple EXEC clauses. A uint4 stores four return addresses rather than copying
register frames. PC/depth/work counters plus that vector add28 private bytes.
Supported CF is NOP, EXEC/EXEC_END, unconditional CALL/JMP and RET. Empty-stack
RET falls through, and EXEC_END terminates even within a called routine.
Position commits only after a complete successful execution. Bounds failures,
unsupported work and call-depth exhaustion commit only status, preserving the
payload and guard. A4096-CF-step limit returns status5 on cyclic/excessive work.
This is a validation limit: continuations or equivalent full valid-program
coverage are required before selecting it for rendering.

Missing: predicates/conditional CF, loops, fetches, relative addressing, remaining
ALUs, pixel RNE arithmetic, other stages/exports and ROP. The64-vec4 private
register file can spill; retail throughput is not established. None of these
modules is linked or selected by the core's Make/CMake source lists. The actual
Vulkan/D3D12 draw-path translation, PSO creation and compilation-wait violations
remain unresolved. This does not certify correct first draws or cold-play fluidity.

C89 procedural corpus and ownership
----------------------------------
shader_control_program_fixture.h adds743 actual GPU invocations over three data
replays,315 of them checked against the real CPU ShaderInterpreter. The existing
>300 reference-comparison floor is retained. Literal four-lane goldens separately
anchor clause dependencies, four nested calls, forward/backward jumps, CALL-next,
empty RET, termination inside a callee, partial export accumulation, zero inputs
and constant windows. Shared descriptors exercise native, big and mixed endian
views of the same packed program records. Later groups vary modifiers/swizzles.
Malformed/cyclic programs are not run through the unbounded CPU oracle.

Negative data exercises depth exhaustion, cycles, invalid CF targets, invalid
ALU spans/counts, unsupported conditional CF/fetches and failures after an earlier
position export. All output guards/failure payloads and input program bytes are
checked. One active module/PSO is retained across the data replays. Normal tests
create one PSO; profiling creates two during initialization, retaining the first
and its explicit private cache for the primed-cache comparison. The test driver
exits without destroying potentially pending resources on failed completion,
following the existing vertex-fixture ownership policy. This is test-only code.

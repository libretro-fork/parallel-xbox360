Direct temporary-read fast path (2026-11-10)
==========================================
First parent: 6c14f39bae370b860b17dba4e80255b611437a46.

The control validation kernel previously loaded its loop-address vector for
every temporary operand, selected zero for a direct operand, added that value
and checked the resulting index. Direct indices are already masked to 0..63.
They now branch directly to the register load. Only relative operands load aL,
add it and enter the adjusted-index guard. The source value still has one final
register load; no alternate register frame, payload copy or allocation is added.
SPIR-V Phi inputs identify the actual predecessor after the relative guard.

The control module grows from 7516 to 7558 words, trading 42 words for less work
on direct reads. It retains three functions and three implementation loops;
arithmetic/program modules remain byte-identical at 2855/6051 words. There is no
GLSL parsing, added capability, float/64-bit shader type or per-program pipeline.
No production build source or renderer call site consumes this validation kernel.

Limits
------
Driver disk/internal caches are not certified cold. First-creation and initial
completion observations cannot establish cold-boot gains. No threshold or cache
default changes were made. This recovers only part of the earlier control-kernel
runtime increase, and establishes no retail throughput/frame-time improvement.
Register spilling/occupancy and full runtime cost need further measurement.

The kernel remains unlinked from rendering. Empty-loop semantics, predicates,
other addressing/ALUs, fetches, pixel/stage/ROP coverage and valid-work
continuations remain incomplete. Actual draw-path compilation and compile waits
are unresolved. No installed core, game or live cache was changed.

Checked loop-relative temporary writes in the continuation prototype
===================================================================

Scope
-----
This extends xe_alu_control_resume_spv_build, not the live renderer. Accurate
ready fallback coverage, fetch, complete stages/ROP and removal of existing
draw-side translation/module/PSO creation and waits remain unfinished. No
gameplay or cold-play improvement is claimed. Original arithmetic, program
and non-resumable control entries remain byte-identical to the parent within
each matched toolchain. The continuation descriptor/state ABI remains 1.

Implementation
--------------
New emission/runtime algorithms are MSVC C89. Vector and scalar temporary
destinations may add the innermost aL value, only after the instruction's
predicate and destination's nonzero mask pass. Direct writes skip the aL load.
The existing checked 64-register window rejects adjusted indices outside it
with terminal status3; no new wrapping/clamping behavior is asserted. Export
bit14 keeps its literal-zero meaning, and export bit6 remains unsupported.

The adjusted index is used for both copy-on-write register lookup and dirty-bit
publication. Partial writes preserve the other lanes; vector then scalar writes
to the same register retain the scalar result where masks overlap. The same
320-word continuation slot retains results across GPU dispatches. There is no
new allocation, host-normalized program, register-bank snapshot, release
timer/logging, wait or compilation worker dependency.
Existing first-write lane preservation and output/state stores remain necessary.

The continuation module grows from12911 to13094 words (+183, about1.42%). It
still reserves16384 words once on cold construction and reuses that allocation
for1000 exact subsequent builds; no function-local64-register array returns.

Continuation constant-address operands (2026-11-16)

Extend only xe_alu_control_resume_spv_build. Decode each consumed constant's
address flag by its raw operand ordinal and the preceding temporary selectors,
not by the number of operands the opcode happens to use. This includes scalar
ADD_CONST0. A consumed loop-relative source borrows aL and the constant-bank
descriptor, checks the bounded view and loads directly into the final operand.
No per-program shader generation, constant-bank copy, allocation, lock, timer,
new state slot or continuation host readback is introduced. Existing endian,
swizzle, negate and absolute modifiers remain after address selection.
Unsupported a0-relative actual reads return status3; unused or masked operands
must neither read that address nor reject the otherwise supported instruction.

The current CPU interpreter supplies a bounded [-256,256] operand index while
retaining raw loop progress; this prototype follows that policy. The initial
uncommitted fixture incorrectly expected raw257/260 for new cases101/126.
The preliminary R400 sequencer document, Exhibit2039v2.11page24, distinguishes
computed loop progress from the bounded indexing output. The corrected new
goldens use operand256, with all initial failed experiments retained externally.
No previously accepted regression golden or threshold was changed.

IMPORTANT: the existing specialized GPU translator retains unbounded loop sums
when addressing constants. CPU/prototype agreement at the bounds does NOT prove
console accuracy or specialization equivalence. Resolve this policy with stronger
hardware evidence before activating this kernel as the renderer fallback.
Do not silently clamp the specialized renderer or remove the boundary cases.
Full fetch, remaining stages, raster output and draw-path compile/wait removal
also remain missing. The general cold-play goal is not achieved.

128 C89 packed-program cases, two endian modes and budgets1/7 cover vector
operand ordinal selection, scalar temporary/constant combinations, modifiers,
lazy unused/a0 reads, positive/negative loop steps, constant bank/window ends,
zero-sized banks, out-of-range sums and continuation persistence. One initialized
pipeline serves all cases. Each replay records64 continuation dispatches with
GPU barriers and one final fence; no per-pass readback or whole-register-bank
checkpoint copy. Inputs, constants, program and context remain borrowed and
immutability/redzones are checked. The preexisting48 relative-write cases retain
their original180 native/literal comparisons through a shared C89 test adapter.

The native reference's SQ_VS_CONST base/size fields have nine bits. A base512
descriptor is valid input to this prototype's bounded-view test but cannot be
represented by that CPU register ABI. The bridge now rejects such metadata
before touching output; four calls verify rejection and sentinel preservation.
Every positive GPU case still has its independent literal check. Expected
coverage is492 native comparisons,496 literals and4 explicit adapter rejections,
not a falsely claimed496 native comparisons against a truncated window.

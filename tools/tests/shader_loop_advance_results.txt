Loop progress and operand-address bounds (2026-11-16)
===================================================
Parent: 615dcdaece9aa44ad5b8d67cb59f97404d49ff54.

The CPU helper saturated its stored aL after every iteration. An enclosing loop
that exceeded the operand range therefore lost progress before a nested REPEAT
could inherit it. Both native GPU translators instead retain the full sum.
Keep the existing four fixed entries and raw progress; clamp only when the CPU
reads the operand address. Unsigned addition and a four-byte bit transfer define
corrupted-state overflow without signed overflow. Legal loop sums fit int32.
There is no heap allocation, payload copy, lock, timer or GPU synchronization.
The four-byte local memcpy is a scalar bit transfer, not a shader-buffer copy.

Independent witness: outer count3/start255/step127, inner REPEAT count5/step-127.
Only the fifteenth body iteration consumes a relative register. The final raw
address is1, selecting initialized r10=42 through base9. The old saturated
iterator selects r13=13. All other relative reads are inactive. The native CPU
and actual Vulkan vertex shader must export four42s; the historical parent must
reproduce four13s, explicitly recorded as a known failure, not a correct oracle.
Triangle capture checks all three vertices and feedback redzones. Original seven
repeat-loop fixtures remain separate and required; no existing case is dropped.

Specification scope: upstream 8dc77b0 shader_interpreter.h cited IPR2015-00325
for its operand clamp. Exhibit2039, R400 Sequencer Specification2.11, page24,
describes the index as iterator*step+start with bounded indexing output. It does
not justify destroying loop progress at each increment. The operand clamp is
preserved here. This preliminary R400 document and PC GPU agreement do not
establish full Xenos conformance, especially relative operand accesses outside
the register/constant windows, empty loops or repeat inheritance at the bounds.

D3D12 derived-system-constant snapshots
=====================================

Runtime scope and ownership
---------------------------
D3D12 Native bindings generate the existing 688-byte SystemConstants directly
into an inactive typed CPU slot. The C89 snapshot helper compares cacheable CPU
slots and swaps their pointers when bytes change, replacing a vector shadow and
its assign copy. Required zero-initialization, register/derived-field generation
and shader layout are unchanged. Byte comparison preserves padding, signed zero
and NaN bit-pattern behavior; no float comparison/quantization is introduced.

Both slots belong to the GPU command processor. Its stable, noncopyable,
nonmovable ownership is checked against the actual class at compile time.
Pointers refer to live typed slots, not raw storage or a borrowed D3D UPLOAD
mapping. Only the recording owner mutates them. Moving such an owner would
require reinitializing the pair; current class ownership disallows that.

Changed constants invalidate the existing GPU binding; unchanged constants do
not. Frame-start invalidation still forces an upload even with identical data.
The required memcpy into constant_buffer_pool_->Request output is preserved.
A failed request leaves the binding invalid, even though the CPU snapshot has
committed. An identical later draw therefore retries the GPU upload. Existing
root dirtiness updates and Native tessellation/system bindings are unchanged.
No GPU readback, synchronization, allocation, lock, logging, timer, audio or
frame-pacing mechanism is added. Upload-pool/driver allocations still remain.

Storage tradeoff
----------------
The old persistent payload was a vector control block plus 688 heap bytes,
with another 688-byte local generation temporary. New persistent payload is
two inline typed slots (1376 bytes) plus 24-byte pointer/valid state on tested
x64 builds. It removes the heap allocation and local generation payload while
retaining an additional 688 bytes of persistent CPU member storage after the
old shadow would have allocated (excluding allocator overhead/class padding).
No claim is made that compiler total stack frames or process RSS shrink.

Validation
----------
- C89 state/reference fixture: 98,304 exact dirty decisions and modeled upload
  sequences across 12 sizes (1..4096 including 688 bytes), poisoned first use,
  unchanged snapshots, changed tails, frame invalidation, failed request followed
  by identical retry, reset with poisoned data and balanced fixture teardown.
- GCC 13.3 -std=c89 -pedantic -Wall -Wextra -Werror + ASan/UBSan passes.
  MSVC 19.44 /TC /O2 /W4 /WX and MinGW GCC 16.2 C89 fixtures pass.
- A thin MSVC boundary calls the C89 fixture with the actual SystemConstants
  sizeof (688), verifies typed array stride and reports alignment (4 bytes).
  A compile-only mode checks actual D3D12 processor copy/move traits. It is
  deliberately not linked: that header also includes unrelated static emulator
  initialization. No fake unconstructed command processor is used.
- Actual D3D12 and Vulkan command processors, deferred/shared implementations
  compile with MSVC. Prior command-page, upload, memexport, descriptor and
  submission-ownership tests pass. Static Windows Make -j5 rebuild/link passes.
- Tests model constant-upload memory with CPU byte arrays. The real register
  generation path was source-audited/compiled, not driven by an emulator fixture.
  No GPU device/driver/gameplay test, FPS, RSS or latency claim.

  compile core_snapshot_pair_test.c as C with XE_SNAPSHOT_BRIDGE;
  link that object with core_snapshot_pair_layout_test.cc as C++20;
  separately compile the latter with XE_SNAPSHOT_OWNER_CHECK, without linking.

Benchmark-only C++ uses the actual constant type, old vector assign and local
payload versus typed inline slots, identical synthetic constant generation,
byte compare and CPU upload copy. It does not reproduce register-cache lookup
or native driver cost. Seven interleaved paired samples of 200,000 draws use
noinline producer/consumer boundaries (GCC noipa), checksum and equal upload
counts; frame invalidation every 257 draws. Timing is median ns/draw. Cold
population is untimed; repeat loops assert no additional vector allocations.
Shadow-copy byte counts accumulate all seven samples plus cold initialization.

These CPU fixtures improve changed-every-draw cases, with small regressions in
some rarely-changing GNU cases. Pointer swapping removes the earlier candidate
index/stride calculation, but is not universally faster than stack generation.
The unused index-based prototype is not shipped. The production benefit claimed
is removal of a heap owner and changed-snapshot copies with exact behavior,
not universal throughput improvement or elimination of all runtime allocation.

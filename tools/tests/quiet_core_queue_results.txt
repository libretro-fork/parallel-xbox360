Quiet frontend logging and C89 timer admission, 2026-11-09
Parent: e2c9faaa0e46ad1e340c1643a26ff87fa0fd8c08

Changes
- Delete the asynchronous logger, its thread, 8 MiB payload buffer, sequence
  metadata, file/stdout/debug/logcat sinks, fragmentation and flush waits.
- Routine macros discard arguments; inline severity guards also eliminate
  debug-only packet disassembly. Frontend varargs calls discard routine levels
  before evaluating arguments. Warnings/errors borrow one complete message.
- Replace 64 KiB per-thread formatting storage with bounded 4 KiB storage.
  Clamp format_to_n's logical length; reject recursive frontend callbacks.
- No logger object or sink allocation, log file, queue reservation, thread ID
  lookup, frame-prefix formatting, or logging thread remains. The independently
  required guest-progress counter is preserved. Frontend output may itself do
  I/O; errors/warnings are deliberately retained.
- Replace disruptorplus timer admission with C89 caller-owned record leases.
  Typed shared_ptr slots, deadlines, recurrence and active timer lists remain;
  this does not remove all timer allocations or claim lock-free waiting when
  capacity is exhausted. Saturated/idle paths park through eventcounts.
- Delete cxxopts and unused standalone command-line entry points; preserve the
  CVar/core-option system and Android bundle parser.

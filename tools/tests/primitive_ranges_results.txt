Primitive restart metadata: scope and reproducible checks
=======================================================

Production changes
------------------
Replace only PrimitiveProcessor::single_primitive_ranges_ with a C89 owner.
VGT_DRAW_INITIATOR.num_indices is 16 bits; DMA_SIZE can only reduce it.
The smallest positive-output segment needs two indices (line loop) and a
reset separator: floor((65535+1)/3) = 21845 rows of 12 bytes, 262140 bytes.
Allocate and touch storage at initialization, reset only count per draw,
and release it outside the memory-invalidation-handle guard at shutdown.
Capacity/count failure is explicit; unpublished tail writes do not alter
the previously published prefix. Borrowed row views end before clear/close.
Do not copy initialized owners or replace retained reset segmentation with
a second scan of mutable guest memory. Input payload remains borrowed.

The installed MSVC 14.44.35207 deque implementation uses a one-element block
for a 12-byte element; clear() calls _Tidy(), freeing blocks and the map.
The replacement removes those allocations from this specific warm path.
This is not evidence about all compiler versions, FPS, RSS or all allocations.

Correctness
-----------
run_primitive_ranges_tests.cmd: MSVC /TC /O2 /W4 /WX.
run_primitive_ranges_tests.sh: strict C89, optional ASan/UBSan.
Checks exact maximum capacity for both widths, guards, retained snapshots,
append rollback, overflow/invalid input, cold-allocation failure, double-init,
idempotent close and 2000 warm reuses with no further allocation calls.
Actual compiled primitive_processor.cc fixtures cover 2048 range/count cases,
80 built-in layouts, 64 initialization policies plus 64 failure replays,
and a persistent owner with 256 warm calls and no test-output-copy mode.
Linux production-source sanitizer coverage instruments the changed source,
bridge and driver; linked dependencies are prebuilt, not fully instrumented.
Full MSVC Release/LTO-OFF and static MinGW core builds are also required.

Warm CPU comparison (separate from shader / gameplay acceptance)
---------------------------------------------------------------
primitive_ranges_ci.py takes exact first-parent --base / --head, clean
--parent-source / --head-source and matched Release/LTO-OFF native builds
--parent-build / --head-build, plus a fresh --out directory.
Run from a vcvars64 environment; only MSVC/Windows is currently qualified.
Builds finish before timing, at three jobs. One common C89 driver/typed ABI
links the actual parent/candidate archives. Archive/input/compiler hashes,
normalized primitive compilation commands, source revision/content and
executable hashes are recorded and checked after measurement.

Pin one CPU (--cpu-group 0 --cpu-index 2 by default) and verify affinity.
32 cases: four topologies, 16/32-bit input, 510/65535 indices, two reset
densities. Validate independent exact rows/guards before and after timing;
retain a persistent owner, with no test-only output row copy during timing.
Perform 16 per-case warm calls and exclude/retain trial zero per order.
Keep seven alternating parent/candidate pairs in forward and reversed case
order. Wall ns/call is primary, process CPU time supplementary. Save every
raw sample and per-case median/p95/p99/max; with seven samples p95/p99=max.
Reject a case when its median exceeds BOTH 5% and 100 ns/call and at least
five of seven matched pairs do likewise. Preserve isolated noisy samples.
No retries until green, no threshold changes, no aggregate-only acceptance.

--negative-control adds real repeated collection work to candidate case 0
only; both orders must reject it. It never qualifies as a performance pass.
--self-check permits dirty/equal revision labels for harness development,
but cannot qualify a commit. Analyzer/protocol units reject malformed or
missing metrics, wrong work/role/order/affinity, dirty/mismatched sources,
changed linked inputs and mismatched compilation flags.

The full existing 768-metric first-parent shader gate remains required.
Publish raw comparison artifacts with the delivered mailbox patch. This
component harness does not measure cold play, GPU rendering, FPS or RSS,
and does not resolve accurate fallback/draw-path compilation violations.

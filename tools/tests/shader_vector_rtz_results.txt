Production and ownership
------------------------
Software-RTZ vertex add/subtract/multiply previously emitted the same exact C89
integer recipe once per component, extracted three operand/native-result words
per lane and rebuilt the float vector. Emit one lane-wise recipe with the whole
scalar/vector IDs instead. The same 32-bit integer math, finite/non-finite
selection, signed FTZ, ordered arithmetic and uncontracted native exceptional
fallback remain. No cross-lane arithmetic, new FMA, precision relaxation or
shader Int64/Float64. Pixel and hardware-RTZ paths are unchanged.

The typed SPIR-V adapter already supports scalar/vector constants, booleans,
bitwise/select/CLZ and 32x32 extended product operations. Product result structs
now use the existing simple-result type interner, matched by both member type
IDs in the current module, instead of a fresh named struct per multiply. No
new interner, cache, state table, buffer, lock, allocation policy or diagnostic.
Vector/scalar member types remain distinct; IDs do not survive module reset.
Borrow original IR IDs and fixed constant views; remove the four-ID component
reconstruction array and redundant extract/construct instructions. Other IR and
driver allocations remain. No whole shader buffer or cache-file copy is added.

pacing benefit is established. No RetroArch/game launch or extracted game assets.

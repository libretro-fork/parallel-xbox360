Runtime
-------
Replace the shared worker parking mutex/condition with per-worker eventcounts.
Count registration before exposing its atomic token. The sole producer/control
owner claims at most one token, rotates selection and notifies that worker only.
Workers recheck readiness and token ownership after preparing the eventcount;
a notification before prepare plus another consumer stealing its job cannot
leave an unregistered sleeper. Busy submission reads one separated counter.
A 128-byte gap separates that read from completion-event writes. Queue slots
remain final payload storage with the original finish lease, without another
allocation, copy or C++ callable wrapper for notification.

Preserve stop limits, reverse joins and joined destruction. Release each worker's
cached backend resources after its context callback returns, and release the
calling thread's cache at retro_deinit after shutdown. The two owned common files
match the RetroArch commit above. The import also includes upstream's Windows
wake-list detachment and Gekko backend changes; this is measured as an integrated
change, not attributed entirely to the new worker selection algorithm.

Correctness and negative controls
---------------------------------
MSVC /TC /O2 /W4 /WX and Linux C89 ASan/UBSan pass. Fresh TSan128/shared-source
runs pass with per-process setarch -R. GCC's known fence-model warning remains
visible (-Wno-error=tsan); this is not a proof that every race is absent.
128 held count/registration/commit and stolen-job windows require producer notify
to return while the worker is held. Fanout holds eight distinct callbacks, bounds
selected wakes to one per job and checks resize/restart/joined teardown.
The parent shared-mutex negative compiles then times out while notify is blocked.
Removing the late token recheck compiles then fails the stolen-job re-registration
check (line63). Correct source passes. Existing pool/typed adapter tests pass.
Windows alert/keyed/event/none tier runs pass. Forced-event lifecycle tests assert
the actual backend and show no handle growth across 32 four-worker lifetimes.
The initial new wakeup prototype without cache cleanup leaked 128 handles in that
scenario (75->203); explicit release holds 71->71. These are separate process
baselines, not evidence of the same leak in the parent's condition-variable path.
Common cleanup/reuse/adoption-failure fixtures pass MSVC, MinGW native, Wine and
forced-semaphore ASan/UBSan; a compiled no-op cleanup negative fails.

Queue figures do not establish compiler throughput, GPU speed or game cadence.

Remaining limits
----------------
Idle workers still park. First backend parking may create a per-thread cache;
this is not complete eradication of mid-game allocation. Cleanup does not release
process-global TLS indices/keyed handles, other threads or separate rthreads
condition-variable caches. Broader unload resource auditing remains necessary.
Blocking admission, draw-side translation/module/PSO creation and compilation
waits remain architectural failures. Accurate ready fallbacks remain unfinished.
No retail replay, sustained gameplay/unload, first-correct-frame measurement,
fresh-process savestate acceptance or certified cold-driver-cache coverage is
claimed. Existing host watchdog/timing and native-emission serialization elsewhere
remain separate debt. This patch adds no release logging, event counters or clock
samples; test hooks compile away. Shader timing passes do not certify cold-play
smoothness or close the broader optimization goal.

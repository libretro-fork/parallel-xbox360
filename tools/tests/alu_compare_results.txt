Implemented semantics
---------------------
The C89 control emitter adds vector SETE/SETGT/SETGTE/SETNE (opcodes4-7) and
scalar SETEs/SETGTs/SETGTEs/SETNEs (opcodes7-10). Vector inputs use the existing
source swizzles/modifiers. Scalar instructions compare the selected W operand
against zero. Results are exact binary32 1/0, unlike predicate setters, whose
existing result convention is unchanged. Ordinary comparisons never update P0.
Scalar results update previous-scalar state even without a destination write;
predication is still sampled before either coissued instruction's effects.

The algorithm uses uint32 binary32 fields and SPIR-V integer/boolean operations:
denormal magnitudes normalize to zero for comparison, opposite zero signs are
equal, and sign/magnitude ordering reverses for negatives. Ordered comparisons
reject either NaN; NE returns true for unordered inputs. No host float mode,
device float-control extension, GLSL source, parser or per-program module is
required. No payload normalization/copy, context bank copy, register-frame copy,
new lock, production diagnostic or per-invocation allocation is introduced.

This modifies the unlinked validation kernel, not rendering. The original raw
arithmetic module remains2855 words and the single-clause program6051 words,
byte-identical to the parent. The control module grows7866 ->8424 words
(+558 words/2232 bytes, about7.1%). Its structural unit-test bound expands for
the new instruction coverage; existing relative/absolute timing and IR-growth
gates are unchanged. Existing C89 output ownership grows during initialization
if needed; 1000 subsequent same-owner builds retain exact bytes without any
allocation. This does not eliminate first-time initialization allocation.

--------------------

- Four vector comparisons over all144 pairs of twelve binary32 classes,
  both byte orders and four output/modifier forms. Classes include signed
  zeros, signed denormals, signed one, signed minimum normal, signed infinity
  and signed quiet NaN payloads. Forms include full/partial exports, dependent
  temporary output and independently modified/swizzled sources.

  source lanes, empty destination followed by RETAIN_PREV, and predicated

  Alternative source lanes contain values with different expected answers

Remaining architectural work
-----------------------------
Comparison context replays are correctness work outside timed children. They
do not establish throughput for newly supported opcodes. The same old primary
timing workload remains comparable; mixed fault-budget execution costs must not
be mistaken for normal shader execution. Additional initialization/emission
cost is real and must remain visible when evaluating a ready interpreter.

Draw-path translation/module/PSO creation and waits remain unresolved. Missing
stage/fetch/ROP behavior, group-wide break semantics, empty-loop proof, other
ALUs/addressing and resumable valid-work continuation prevent renderer use.
The current program entry also loads operand slots before per-op consumption
is known; unused relative-source handling and unnecessary reads need further
work before full semantic coverage can be claimed. No accurate ready-renderer
fallback, cold-play smoothness or gameplay/frame-time improvement is certified.

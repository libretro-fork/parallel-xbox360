Raw packed-program SPIR-V foundation, 2026-11-10
Parent: 35e17e624d9f57abed5fb42cfb8deb8d0fbcfcae

This emitter is built by validation tools, NOT linked/selected by the renderer.
Draw-side compilation, inaccurate stand-ins and missing accurate fallback remain
unresolved. No retail cold-play/FPS improvement or full shader accuracy is proved.

Implementation:
- C89 raw SPIR-V1.0, Shader capability, 32-bit integer math. No GLSL source/parser,
  external instruction imports, ShaderInt64 or ShaderFloat64.
- Independent ADD/MUL/MAD record module: RTZ, signed FTZ and SM3 zero semantics.
- Packed ABI1 executes one native EXEC_END clause with at most six ALUs: vector
  ADD/MUL/MAD; scalar ADD, ADD_CONST_0, RETAIN_PREV; 64 temps, checked constant
  windows, coissued reads, dependent masks, scalar history and position exports.
- Four borrowed bindings hold descriptors/initial temps, shared programs,
  constants and outputs. GPU loads correct either program byte order. No host
  normalized-code copy is required by this interface. Source resolution loads
  the selected temp OR constant, rather than unconditionally loading both.
- Input owners remain immutable through completion. This does not prove mutable
  guest RAM may safely be borrowed without a shader-load snapshot.
- Failure commits status only, leaving output payload/guards unchanged.
- Initial register loads/private snapshots remain necessary. The 64-vec4 local
  file is 1KiB/invocation; spilling and real VS/PS execution cost are unverified.
- General CF/fetch/predication/relative/clamp/other ALUs, pixel RNE, other stages,
  exports/ROP and sufficiently fast rendering still need implementation.

Correctness/ownership:
- MSVC /TC /O2 /W4 /WX and strict GCC C89; Linux ASan/UBSan and spirv-val Vulkan1.0.
- Two emitted modules: 2875 arithmetic words, 6171 program words (24684 bytes).
  Three functions each, two program loops. Float types/imports and 64-bit shader
  types/capabilities are rejected by the structural C89 fixture.
- 1000 exact same-owner rebuilds per module require zero further allocations;
  initial allocation failure, overflow, recovery and exactly-once close pass.
- RTX5090 driver32.0.16.2101 and llvmpipe LLVM20.1.2 execute 12280 arithmetic
  records and 743 program invocations across three data replays.
- 363 program results compare to the actual CPU interpreter; independent literal
  anchors cover coissue, partial masks, overlap-to-one, zero export and history.
  Finite bits/nonfinite classes are checked; exact NaN payloads are NOT proved.
- Native/swapped/mixed shared programs, register63, zero/partial/full initial
  registers, zero/full constants, constant windows, malformed counts/offsets,
  unsupported/late failures, source immutability and output redzones pass.
- A semantic negative stores vector results before acquiring the scalar source:
  invocation10/fixture5 becomes4.0 instead of3.0. Both native/literal checks fail.
- Normal runs create one PSO. Profiling creates two during initialization,
  retaining the first and its primed private application cache for the second.
  One active module/PSO remains unchanged across all three data submissions.

Reusable C89 operand payloads, Windows x64, 2026-11-05
Parent: complete 4dcf6a696 source archive, including the texture-watch race fix.

Arena instructions allocate combined operand words/flags from exclusive retained
payload pages. Each instruction page has an owner pointer; the existing relative
record offset locates it only on the slow reserve/grow path. No instruction field
or pointer tag is added: local_flags[0], unused when heap words exist, records the
pooled allocation kind after inline ID bits have been copied to the packed map.
Instruction 64 / Block 136 / Function 208 / Module 88 / Builder 2008 x64 sizes remain unchanged.
The out-of-line arena state adds 56 bytes and each instruction page adds 8 bytes.

The latest live payload may extend in place. Its packed flag map moves with
memmove when capacity changes; its operand words and borrowed address do not
move. Non-tail growth copies only initialized words/flag bytes into a checked
replacement. Old pooled spans retire without calling free on interior pointers.
No callback frees the previous allocation. Ordinary malloc-backed stack records
and transitions between ordinary/pooled owners preserve their own release rules.
The counted string encoder first reserves through its instruction's workspace.

Cold InstructionArena and Vulkan geometry setup reserve 16 KiB of payload space.
Larger payloads add checked pages without relocating existing spans. All typed
payloads retire before module end poisons/resets page metadata. Warm leases do
not clear or copy page contents. Workspace close releases the retained pages
after module cleanup; active-lease/object guards still reject premature close.
ASan builds pad spans and add redzones, poisoning freed/replaced spans and entire
ended leases; release builds have no poisoning or redzone overhead. This trades
higher retained memory for fewer shader-time allocations, not lower process RSS.

C89 tests cover two workspaces, 100 allocation-free warm leases, stable tail growth,
copied non-tail growth, overlapping flag-map relocation at 65->66 words, alignment,
allocator-kind transitions, initialization/growth OOM, overflow, rejected active
close/end and unchanged live data after failed reserve. Negative ASan cases read
freed, replaced and ended-lease payloads and must report use-after-poison. Typed
tests verify retired payload views separately from retired instruction records,
orphan/exception cleanup, partial reserves and stable high-water reuse. Previous
malloc-count assertions are replaced by zero per-record malloc and stable page
counts; allocation faults now target actual payload-page growth. Stack heap
failure tests remain in the standalone operand suite.

Shader comparison covers all 18432 geometry variants and 128 validator modules,
5248 EDRAM helper modules, sampler/view/control-flow cases and 1410 actual cached
guest translations across host-RT/interlock profiles. Byte output remains the
same. Native MSVC C89/typed checks and full Make-j5 are part of validation.
No GPU/frontend/game is launched. The installed confirmed-working Tomb Raider
core is kept intact while these allocator changes are checked offline.

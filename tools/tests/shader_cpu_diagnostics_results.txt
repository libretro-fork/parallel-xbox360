Scope
-----
Test/CI-only instrumentation. No production renderer, shader emitter, worker
queue, core timing, audio, cache policy or runtime file I/O change.
The original compare() thresholds and percentile functions are unchanged.
Elapsed time stays authoritative, including tails. A CPU-only view cannot pass
a stalled wall-time result. Process CPU samples are separate raw CSV files and
paired indexed report entries, including anchor coverage. Missing/substituted
CPU roles/cases or sample counts fail rather than silently dropping diagnostics.

Timed binaries use QPC/CLOCK_MONOTONIC for wall and process user+kernel time on
Windows or CLOCK_PROCESS_CPUTIME_ID on POSIX for CPU. Capture CPU endpoints
before file writes and outside the primary elapsed interval. No release hooks
are added; the timing header is only used by test executables. Read executable
hashes in bounded1MiB chunks. Store executable sizes/hashes, exact module
identity, clock-control traces and timing-contract2 in artifacts. Workflow
artifact names include run_attempt; old attempts remain available.

Mandatory timer control
-----------------------
A strict C89 child prints readiness and blocks reading its owned stdin. Test
orchestration holds it for120ms, then releases it; a separate phase consumes
60ms process CPU. Seven repeats must retain >=100ms blocked wall time and
<50ms blocked CPU, and >=40ms busy CPU. The same control verifies that the
injected elapsed stall fails the unmodified comparison gate. MSVC, MinGW and
POSIX GCC controls PASS. The controlled wait is offline fault injection, not
core/frontend frame pacing.

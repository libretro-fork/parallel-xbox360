Vulkan descriptor budget policy and count-only storage (0122)
===========================================================

Move native allocator budget matching, fit/full checks, spending, maxima and
initialization into MSVC C89 helpers. The C++ file retains native dispatch,
existing failure logging and ownership/index transitions. The prepared request
borrows immutable request/type tables and caches indices for one/two-type
requests. Larger requests use generic lookup; there is no two-type limit.
Only cold fallback computes request maxima or checks whether a new pool is full.
MSVC keeps the helpers inline; common fit/spend paths avoid generic loops.

Because candidate checks now use the shared type table, mutable pool budgets no
longer need duplicate VkDescriptorType values. Each counter span is uint32_t[],
not VkDescriptorPoolSize[]. Initialize only counts, and spend directly in that
span. Remove repeated type-ID writes and halve counter payload from eight to
four bytes per type. No temporary counter conversion buffer is introduced.
Native VkDescriptorPoolCreateInfo still borrows the original Vulkan type table.
Native pool sizes, descriptor selection/full policy and GPU ownership are intact.

Storage/lifetime:
- Plan is stack metadata with borrowed tables, no allocation or payload copy.
  Requests/type order must stay immutable until Allocate returns. Mutable count
  arrays keep the owner's configured table order and remain stable in C89 pages.
- Counter page requests on tested x64: 520 + 64*types*4 bytes, previously
  520 + 64*types*8. The four core tables have 1,1,2,2 types: warmed owner pages
  request 3,616 instead of 5,152 bytes, saving 1,536 bytes of requested storage.
  This is not process RSS. Retained capacity and new peak/native allocations
  otherwise follow the previous implementation. No allocation-free core claim.
- Only successful native allocations spend counters; exact type exhaustion or
  the last set slot retires the search node. Full native pools stay owned until
  the existing GPU-safe reset. Unsupported/oversized types use dedicated pools.

Offline verification:
- Strict GCC C89 -pedantic -Wall -Wextra -Werror ASan/UBSan and native MSVC
  /TC /W4 /WX: 300,000 independent scalar cases with permuted table/request order,
  cached one/two requests, generic requests, unknown/oversized types, zero slots,
  final slots, exact exhaustion, maxima and counter conservation. Explicit
  seventeen-request initialization and UINT32_MAX boundary cases pass.
- Retained-owner tests now exercise count-only views across growth/reset with
  three/seventeen configured types; stable pointers, lease gates, checked sizing,
  no post-warm allocation and balanced frees still pass.
- Actual allocator fake-dispatch trace remains 1aed303f01c48a25: 970 native-create
  calls, 1,478 set allocation calls, 1,267 successful sets. Zero C++ new calls;
  all ten C89 metadata failures and 233 logger failures pass with immediate retry
  and exact-once destruction. Pointer/integer Vulkan handle forms pass.
- Native MSVC production allocator/Vulkan command processor compile and full
  Windows static Make -j5 passes. No GPU, game, frontend or JIT is launched.
  Actual rendering/post-unload GPU validation remains unrun.

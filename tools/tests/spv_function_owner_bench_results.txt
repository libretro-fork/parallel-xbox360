C89 function ownership and removal of dead precision metadata, 2026-11-05
Parent: complete 34a3b48d5 archive. Windows x64, GCC 16.2 -O2.

Builder function ownership uses the existing C89 head/tail primitive. A typed
Function link occupies the inline OpFunction header's previously unused void*
slot, with no new per-record field or pointer-to-pointer type punning. Generic
instruction-list access explicitly excludes OpFunction headers. Typed cleanup
borrows next before deleting the current function; its ID unpublication, child
blocks and operand owners still retire before module arena cleanup. The builder
cleans functions before its remaining lookup maps, whose destructors do not
dereference borrowed function records. Constructor/publication keeps unique_ptr
ownership until the nonthrowing append; entry/build-point state publishes last.

Four post-processing walks and final emission use the same creation-order chain.
Emission compares the borrowed terminal function pointer after its block graph,
avoiding a final reload of that header's null link. There is no ownership-array growth or
pointer-array copy. Other maps/vectors and checked arena growth remain.

The per-function reducedPrecisionParams set and its unread setter/query are
removed. Repository callers never read it; makeFunctionEntry's actual global
parameter decorations remain. This also removes the empty tree-node allocation
observed with MSVC. Tests deny C++ allocation during warmed undecorated function publication
and require success without allocation; actual C page failures still prove
unpublished state and cleanup. Duplicate RelaxedPrecision decorations are parsed
from encoded output at 0/1/4/9/70 parameter counts, verifying their continued
presence and deduplication without a second per-function registry.

Measured GCC x64 layouts: Instruction 64 and Block 136 unchanged; Function 208->152,
Builder 2008->2000, Module 88 unchanged. Allocated function pool stride 224->176
because slots remain 16-byte aligned. Native MSVC checks also pass; these GCC
layout deltas are not assertions about every standard-library implementation.

Tests include 257 stable function links across multiple pool pages and ordered
emission, plus normal/exception destruction. Existing C89 operand/arena faults,
orphan cleanup, typed/payload negative use-after-poison, sampled-image rewrites,
eight source/view modules and 5248 helper modules remain covered. All 18432 final
MSVC geometry variants match pre-change GCC bytes. Actual Tekken cache 1410 and
Tomb Raider cache 210 translations remain byte-identical, including 96 Tomb Raider
control-flow cases. The 256-race texture-watch regression also passes. No game,
frontend or GPU is launched; the installed confirmed-working core is preserved.

Paired construction and serialization results follow below; these are not
gameplay FPS/frame-pacing, process RSS or hardware cache/spill-counter results.

Output allocation counts/bytes are unchanged. Serialization is comparable for
the tiny/71-function cases, while the other medians are about 1.8% slower. Linked
ownership and denser metadata do not guarantee a faster emitter. This tradeoff
is retained explicitly alongside construction and storage improvements. No
unmeasured total shader-compilation or gameplay speedup is claimed.

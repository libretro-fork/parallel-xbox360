GPU trace VFS / borrowed compression source (0153)
================================================
TraceWriter now owns a zero-initialized C89 xe_trace_stream backed by owned
libretro-common RFILE/VFS. Its public Open takes UTF-8 rather than filesystem::path;
the existing two native command-processor path producers adapt once when opening.
C89 parent creation preserves relative/VFS paths instead of canonicalizing them
through std::filesystem. Paths>=4096 bytes are rejected without truncation.
TraceWriter headers no longer require filesystem or unconditional set/string
headers. Other renderer/trace path producers still use std::filesystem; this
is not a claim that the full I/O migration is complete.

Borrowed payload writes use the existing checked cache-file transfer helper.
Short writes/EINTR advance the original span; no payload staging is added.
Compressed-record header patching captures the actual int64 end, validates
payload length and cursor bounds, patches then restores that end. VFS seek
returns status: success is checked and tell verifies the cursor independently.
Invalid count/stride/null payloads fail before compression/pointer arithmetic.
Transfer/tell/seek/flush failure latches the stream so later records cannot
append after an unpatched header. Close always attempts resource release, and
the writer destructor now closes instead of default-destroying an open file.

Gamma compression uses a C89 two-span source through a minimal native Snappy
adapter. The old2560-byte concatenation allocation is gone. Snappy already
allocates its input working block unconditionally; it gathers a split source
there. Thus an extra intermediary allocation disappears, while the required
block-gather byte copies and Snappy working-memory allocation remain. No claim
of end-to-end zero-copy, allocation-free capture or asynchronous I/O. Existing
cached-read set nodes and cold path-string conversion also remain.

Removed DumpEdramSnapshotToFile / WriteEdramSnapshotToFile in the base command
processor, both backends and common render-target cache. Repository-wide search
found no core caller reaching that standalone raw-file API. This removes dead
submission/wait/map/stdio code, not active GPU readbacks. Trace initialization's
required readback/map/end lifecycle is retained. No graphics synchronization,
frontend pacing, audio or content-close join change. Release trace instrumentation
remains disabled unless explicitly enabled; no release profiling counters added.

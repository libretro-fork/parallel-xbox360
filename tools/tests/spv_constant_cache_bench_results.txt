Retained exact-key shader constant cache, 2026-11-05
Parent: complete 985d56eb9973e7cb8caa4f2029a7d44cde9f5161 sources.
Windows x64 GCC 16.2 -O2; native MSVC and WSL ASan/UBSan checked separately.

Two unordered maps of instruction vectors and the null-constant vector are gone.
One exclusive C89 open-addressed table indexes regular scalar, bool, composite,
struct and null constants. Slots store only a borrowed record pointer, 32-bit hash
and epoch (16 bytes on measured x64). Exact comparison checks opcode, type ID,
operand count and raw operand words after a hash match. Operand bits distinguish
signed zero and NaN payloads; 64-bit high words and composite member order remain
part of the key. Words remain owned by immutable instruction operands, with no
key-payload allocation/copy. Instruction/global output order is unchanged.

Specialization constants bypass canonical lookup/insertion to keep unique IDs.
An old struct lookup ignored opcode and could return an earlier specialization
constant as a regular constant. The new exact lookup fixes this; the comparison
script reproduces the old alias and verifies the corrected separate IDs. Ordinary
fixture bytes and actual game translation bytes below remain identical. Folded
replicated composites reserve only their encoded member count, not the expanded
caller member count.

A workspace retains table high-water capacity in its C arena state. Cold x64
compiler setup prefaults 256 slots (4 KiB), enough for 192 regular constants at
the 75% load limit. Larger modules grow with checked allocation. Growth rehashes
only slot metadata, never operands. Failed growth retains all existing entries;
publication reserves first, completes the throwing ID map, then inserts/appends
without allocation. Module end advances the epoch; no reset reads retired record
payloads. Epoch wrap clears slot metadata. Arena close frees the table through
the same allocator as growth. Lookup is single-compiling-owner, without locks,
atomics or release profiling/logging counters. Other type/debug maps and shader
metadata still allocate; this does not eradicate all runtime allocation.

GCC x64 Builder 2000 -> 1864 bytes; Instruction 64, Block 136, Function 136 and
Module 88 unchanged. The C arena object state gains 32 bytes. Reusable storage
trades a larger retained footprint for eliminating per-module constant-container
allocation and repeated linear scans. Retained capacity is not a memory leak.

Construction workload: 16/256/2048 distinct integer and float values plus pair
composites (40/640/5120 total constants), then three complete repeated-lookup
passes. Counted construction includes all builder cleanup, excludes serialization
and file I/O. A warm untimed dump writes each module for exact byte comparison.
Seven alternating quiet parent/current pairs after all compilers stopped. Each
revision uses its own complete C/IR source snapshot and the same typed fixture.
All C++ new and C operand, arena, index, plan and output allocations are hooked;
allocator headers/retained free blocks and driver memory are excluded. Tracked
live storage returns to the initial state at close; workspace high-water memory
stays constant across repeats.

The medians are about 2.62x/26.48x/188.15x faster for these deliberately
constant-heavy synthetic construction/lookup workloads. This is not a claim
about overall translation, driver compilation, gameplay, FPS or stutter. Current
allocation requests are 18 per module versus 36/48/57 (50%/62.5%/68.42% fewer).
The largest requested-byte reduction is 97.49%. Other allocations remain.

Retained bytes increase by 4128/16416/131104: 4/16/128 KiB slot storage plus the
32-byte state. Peak tracked storage also increases by 3552/10560/85824 bytes.
These tradeoffs are explicit; no RSS/cache-miss/register-spill improvement has
been measured. Serialization throughput was not separately remeasured here.
